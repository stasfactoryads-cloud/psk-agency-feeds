# Фиды ГК «ПСК» для агентств недвижимости

Сервис собирает YRL-фиды по 11 объектам ГК «ПСК» для агентств «Тренд», «Адвекс»,
«Петербургская недвижимость», «ПАН» и «Н Маркет». У каждого агентства отдельный фид
на каждый объект. Формат соответствует техтребованиям Яндекс Недвижимости
(продажа в новостройках). Данные берутся из API psk-info.ru.

**Страница со ссылками на фиды:** https://feedhub.realty/feed-evel/

Файлы лежат на хостинге REG.RU (папка `/feed-evel/` сайта feedhub.realty).

## Как это работает

GitHub Actions ([update-feeds.yml](.github/workflows/update-feeds.yml)) каждый день в 12:00 МСК:

1. **Сборка.** Загружает лоты из API сайта, конвертирует планировки SVG в JPG
   и собирает фид для каждого агентства и объекта.
2. **Аудит.** Проверяет фиды по правилам Яндекс Недвижимости и наличие всех картинок,
   сверяет набор лотов с API, следит за резким падением их числа и за свежестью фидов.
3. **Загрузка на хостинг.** По FTP отправляет `docs/` на REG.RU (4 параллельных соединения).
   Файлы вне `feeds/`, `preview/`, `plans/` на хостинге не трогаются.
4. **Фиксация.** Коммитит в репозиторий фиды и статус (картинки в git не хранятся).

Если сборка или аудит не прошли, загрузки нет: на хостинге остается последняя
корректная версия, а GitHub присылает владельцу письмо об упавшем запуске.

Запустить обновление вручную: вкладка **Actions** → «Обновление фидов для агентств» → **Run workflow**.
После правки `config.toml` фиды пересобираются автоматически.

Доступ к хостингу хранится в секретах репозитория: `FTP_SERVER`, `FTP_USERNAME`,
`FTP_PASSWORD`, `FTP_PATH` (`/`, потому что FTP-пользователь входит сразу в папку проекта).

## Страница со ссылками

Главная страница (`index.html`) показывает агентства списком-аккордеоном. У каждого агентства:
- кнопка «Скопировать все ссылки»: в буфер попадает готовый текст с описанием, сайтом,
  телефоном, руководителем отдела, ссылками на все фиды агентства и контактом бота поддержки;
- таблица фидов по объектам с кнопкой «Копировать» у каждой ссылки.

Тексты (сайт, телефон, руководитель, бот поддержки) задаются в блоке `[portal]` файла `config.toml`.
Пересобрать только страницу без обращения к API: `python -m feedgen portal`.

## Статусы квартир и собственные поля

В сборку попадают лоты со статусами «Свободно» и «Бронь» (`include_statuses` в `config.toml`).
В каждом объявлении есть два собственных поля ГК «ПСК». Стандартных тегов для них в требованиях
Яндекса нет, поэтому у полей префикс `psk-`:

```xml
<psk-flat-number>838</psk-flat-number>      <!-- номер квартиры на сайте застройщика -->
<psk-flat-status>свободна</psk-flat-status> <!-- свободна или бронь -->
```

Номер квартиры уникален только внутри корпуса: у разных корпусов бывает одинаковая нумерация.
Корпус указан в теге `building-section`.

Агентство, которому нужны только свободные квартиры, настраивается в `config.toml`:
`include_booked = false` в блоке агентства (по умолчанию `true`).

На странице со ссылками есть блок «Статусы квартир»: по каждому объекту свободно, бронь и
изменение с прошлой сборки. Аудит сверяет статусы в фидах с сайтом, сообщает о новых статусах
на сайте и о резком росте числа броней.

## Что в фиде

| Блок | Источник |
|---|---|
| Цена, площадь, этаж, комнаты, отделка, срок сдачи | `api/flats/` (список лотов) |
| Высота потолков, балкон | `api/flats/<id>/` (карточка лота) |
| Описание лота | параметры лота + преимущества проекта из API |
| Планировка квартиры (`<image tag="plan">`, первая картинка) | SVG `plan` -> JPG |
| Поэтажный план с подсвеченной квартирой (`tag="floor-plan"`) | SVG `floor_plan` + контур `floor_plan_hover` -> JPG |
| Рендеры ЖК | `slider_images` проекта |
| Привязка к каталогу Яндекса | `yandex-building-id` и `yandex-house-id` из `config.toml` (у большинства объектов свой ID на каждый корпус, `house_ids`) |
| Продавец | телефон, менеджер, название агентства из `config.toml` |

Описания проходят проверку по правилам ГК «ПСК»: нет буквы «е» с точками, длинного тире
и телефонов, есть название ЖК и «ГК «ПСК»». Порядок пунктов о проекте зависит
от агентства, поэтому тексты у агентств не совпадают дословно.

## Настройка

Все настройки лежат в [config.toml](config.toml), код править не нужно:
- агентство: блок `[[agency]]` (телефоны, менеджер, название, UTM-метка,
  список ЖК `projects`; без него агентство получает все ЖК);
- ЖК: блок `[[project]]` (ID в API сайта, ID в каталоге Яндекса, отделка);
- скидка: `show_discount` (перечеркнутая цена в Яндексе или только упоминание в описании);
- отделка: соответствие значений сайта и Яндекса в `[project.renovation]`.

Правку можно сделать прямо на GitHub (иконка карандаша у файла), фиды пересоберутся сами.

## Структура

```
config.toml                  настройки проекта и агентств
feedgen/                     код генератора
  api.py                     клиент API psk-info.ru
  images.py                  SVG -> JPG, подсветка квартиры на поэтажном плане
  description.py             текст описания лота
  yrl.py                     сборка XML в формате YRL
  validate.py                правила Яндекс Недвижимости
  audit.py                   аудит набора фидов перед публикацией
  site.py                    страница со ссылками
docs/                        публикуемые файлы (GitHub Pages)
cache/first_seen.json        дата первого появления лота (для creation-date)
.github/workflows/           расписание и публикация
deploy/, Dockerfile          запасной вариант: свой сервер
```

## Команды (локально)

```bash
python3 -m venv venv && venv/bin/pip install -r requirements.txt
venv/bin/python -m feedgen build                 # собрать все фиды
venv/bin/python -m feedgen build --agency pan    # одно агентство
venv/bin/python -m feedgen audit                 # аудит
venv/bin/python -m feedgen validate docs/feeds/pan.xml
```

Нужен Python 3.11 или новее.

## Свой сервер вместо REG.RU

Если понадобится другой хостинг, укажите его адрес в `public_base_url` и запустите
`docker compose up -d --build`: сервис пересобирает фиды по расписанию и раздает `docs/`.
Конфиги nginx и systemd лежат в `deploy/`.

## Надежность

- Если API сайта недоступно или вернуло 0 лотов, сборка падает и старые фиды остаются.
- `creation-date` лота фиксируется при первом появлении, чтобы Яндекс не считал
  объявления новыми при каждом обновлении.
- Планировки в git не хранятся: на каждом запуске пересоздаются из SVG (около 10 минут),
  а на хостинг загружаются только те, которых там еще нет (имя файла зависит от содержимого).
- Загрузка на хостинг идет в 4 потока (`FTP_WORKERS`); XML и страницы загружаются каждый раз,
  потому что в них меняется время обновления.
